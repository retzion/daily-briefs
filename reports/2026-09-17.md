## Featured: `CLAUDE_CODE_MCP_STARTUP_WAIT_MS` (MCP Startup Timeout Control)
New in v2.1.274 (Sep 17), this environment variable controls how long Claude Code waits for MCP servers to connect before starting a session.

**Why it matters**: MCP servers that host heavy tools (database connectors, cloud infrastructure managers, custom RAG pipelines) can take several seconds to initialize. By default, Claude Code waits a fixed interval — if your server is slow, the session may start without it; if it's fast, you're waiting needlessly.

**Usage**:
```bash
# Wait up to 15 seconds for MCP servers to connect
export CLAUDE_CODE_MCP_STARTUP_WAIT_MS=15000

# Or set per-session
CLAUDE_CODE_MCP_STARTUP_WAIT_MS=20000 claude
```

**When to use it**:
- Your MCP server hosts a database that needs a connection pool warmup
- You run MCP over a remote tunnel with variable latency
- You use multiple MCP servers and want to ensure they're all ready
- You want faster startup and know your local MCP servers connect instantly (set it lower)

Pairs well with `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` (featured Jul 19), which controls when slow MCP servers are moved to the background instead of blocking.
