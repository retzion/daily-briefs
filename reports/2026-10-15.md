## Featured: `onFailure: "block"` for Hooks

Added in Claude Code v2.1.295 (Oct 8), `onFailure: "block"` lets you configure command and HTTP hooks to **block the tool call entirely** if the hook's command fails (non-zero exit or HTTP error).

**Why it matters:** Previously, a failing hook was informational only — the tool call proceeded regardless. Now you can enforce hard gates: run a lint check before every file write, validate a security scan before a push, or require a custom approval script before destructive operations.

**Quick example** in `.claude/settings.json`:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write",
        "command": "python3 .claude/hooks/lint-check.py $CLAUDE_FILE_PATH",
        "onFailure": "block"
      }
    ]
  }
}
```

If `lint-check.py` exits non-zero, the Write tool call is blocked and Claude sees the hook's stderr output as the reason. This turns hooks from passive observers into active guardrails.
