## Featured: Artifact Database (`read_db` / `write_db`)

Published Claude Code artifacts can keep a **shared, persistent database** — turning static pages into collaborative apps like polls, sign-up sheets, checklists, or dashboards with real state.

**What it is:** The artifact database is a document store organized by collections. Each artifact gets its own database, shared across all viewers. You read/write it from the Claude Code session (not just from the page's JavaScript), using `action: "read_db"` and `action: "write_db"` on the Artifact tool.

**Why it's useful:** Instead of relying on `localStorage` (per-browser, per-viewer, volatile), the artifact database gives you durable, shared state. Everyone who opens the artifact sees the same data. There's also a per-user private space under `data/users/me/` for viewer-specific state.

**Quick usage:**
```
# Write a document
Artifact({ action: "write_db", url: "https://...", db_op: "set",
  collection: "votes", doc_id: "option-a",
  data: { label: "Option A", count: 12 } })

# Read it back
Artifact({ action: "read_db", url: "https://...", db_op: "get",
  collection: "votes", doc_id: "option-a" })

# Query a collection
Artifact({ action: "read_db", url: "https://...", db_op: "query",
  collection: "votes",
  query: { order_by: { field: "count", direction: "desc" }, limit: 10 } })

# Batch write (up to 50 ops, atomic)
Artifact({ action: "write_db", url: "https://...", db_op: "batch",
  writes: [
    { op: "set", collection: "votes", doc_id: "option-a", data: { count: 13 } },
    { op: "set", collection: "votes", doc_id: "option-b", data: { count: 7 } }
  ] })
```

Requires the `db` capability declared on the artifact. Load the `artifact-capabilities` skill first for the full API and per-user data paths.
