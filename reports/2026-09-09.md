## Featured: `--plugin-dir` (Local Plugin Development Workflow)

When building a custom Claude Code plugin, `--plugin-dir` lets you load a local plugin directory into your session without installing it globally. Combined with `/reload-plugins` and `claude plugin validate`, it forms a tight local dev loop.

**What it is:** A CLI flag that additively loads one or more plugin directories for the current session. Your plugin directory needs a `.claude-plugin/plugin.json` manifest, with `skills/`, `agents/`, `hooks/` folders at the plugin root.

**Why it's useful:** You can iterate on a plugin — edit skills, tweak hooks, adjust agent definitions — and see changes immediately without publishing or reinstalling. `/reload-plugins` picks up edits without restarting the session. Before sharing, `claude plugin validate ./my-plugin` checks the manifest, skill/agent frontmatter, and hooks.

**Quick usage:**
```bash
# Load your plugin during development
claude --plugin-dir ./my-plugin

# Load multiple plugins at once
claude --plugin-dir ./plugin-a --plugin-dir ./plugin-b

# Validate before distributing
claude plugin validate ./my-plugin
```
