## Featured: Cloud Session Environment Configuration

Cloud session environments let you configure how Claude Code cloud sessions run — including network policies, environment variables, and setup scripts — before any session starts. This powers use cases from daily automated briefings to CI/CD integrations.

**What it is:** When creating a cloud session (via the web, API, or a scheduled routine), you can specify:
- **Network policy**: Control outbound HTTPS access (allow-all, deny-by-default with allowlist, or no external access)
- **Environment variables**: Pre-set variables like API keys, config flags, or custom paths
- **Setup scripts**: Shell commands that run when the container starts (install dependencies, clone additional repos, configure tools)

**Why it's useful:** Cloud sessions are ephemeral — the container is reclaimed after inactivity. Environment configuration makes them reproducible. A team can define a standard environment once and every session starts identically, whether it's a human kicking off a task or a scheduled routine running overnight.

**Quick example:** This very daily briefing runs as a scheduled routine in a cloud session with:
- A network policy allowing outbound HTTPS (for web searches and GitHub)
- A Google Drive MCP server configured for document updates
- A GitHub MCP server for repo operations
- The repo cloned fresh at session start

**Docs:** [code.claude.com/docs/en/claude-code-on-the-web](https://code.claude.com/docs/en/claude-code-on-the-web)
