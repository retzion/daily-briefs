## Featured: `availableModelsMatch` & `deniedModels` Managed Settings

New in Claude Code's late September releases, these two managed settings give enterprise administrators precise control over which models are available in Claude Code sessions across their organization.

**What they do:**
- `availableModelsMatch` — a whitelist pattern that restricts sessions to only model IDs matching the pattern (e.g., `"claude-opus-5*"` to allow only Opus 5 family models)
- `deniedModels` — a blocklist of specific model IDs that are forbidden regardless of other settings (e.g., block an older model with known issues)

**Why it matters:** As the model roster grows (Opus 5.5, Opus 5, Sonnet 5, Fable 5.1, Haiku 4.5), organizations need guardrails to ensure developers use approved models — for cost control, compliance, or capability requirements. These settings complement the existing `enforceAvailableModels` setting (featured Jun 13) by adding pattern-matching and explicit deny capabilities.

**Usage example** (in managed settings JSON):
```json
{
  "availableModelsMatch": "claude-opus-5*",
  "deniedModels": ["claude-opus-5-0"]
}
```
This allows any Opus 5.x model but blocks the original Opus 5.0 specifically.
