## Featured: OpenTelemetry Export for Claude API (Public Beta)

Anthropic's OpenTelemetry tracing integration, which entered public beta on October 14, lets you pipe structured traces from every Claude API call into your existing observability stack.

**What it is:** Two layers of tracing that can be combined into a single trace:
- **SDK-side tracing** — enabled in code via the Anthropic SDK; spans cover your application's calls to the Messages API, including tool use
- **API-side tracing** — enabled by an org admin adding an OTLP/HTTP destination in the Claude Console; spans cover Anthropic's server-side processing

When both are active, the SDK span wraps the API span, giving end-to-end visibility from your app through Anthropic's infrastructure.

**Why it's useful:** If you run Claude in production, you can now see latency breakdowns, token counts, error rates, and tool-call timings in the same dashboards where you monitor everything else. Named backends include Datadog, Grafana, and Langfuse.

**Quick setup:**
```python
import anthropic

client = anthropic.Anthropic(
    # SDK tracing — set your OTLP endpoint
    telemetry=anthropic.Telemetry(
        otlp_endpoint="https://your-collector:443",
        service_name="my-claude-app",
    )
)
```
For API-side tracing, an org admin configures the OTLP/HTTP destination in the Claude Console under Settings > Observability.

**Caveat:** Still in beta — span names, attributes, and SDK options may change between versions. Pin your SDK version.
