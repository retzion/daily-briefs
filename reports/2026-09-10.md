## Featured: `maxEffortLevel` Setting

New in v2.1.267, the `maxEffortLevel` setting caps the reasoning effort level that Claude Code applies across all providers — including Bedrock, Vertex, and Foundry where effort controls may behave differently or cost more.

**Why it's useful:** Effort level directly affects token consumption and latency. On large codebases or when running many subagents, uncapped effort can burn through usage limits quickly. `maxEffortLevel` gives teams a simple guardrail — set it once and every request respects the ceiling, regardless of which model or provider is in use.

**Configuration:**

```jsonc
// Global cap in settings.json
{
  "maxEffortLevel": "high"  // caps at "high" — blocks "max"
}

// Per-model cap under modelSettings
{
  "modelSettings": {
    "claude-opus-4-6": {
      "maxEffortLevel": "max"
    },
    "claude-fable-5-1": {
      "maxEffortLevel": "medium"
    }
  }
}
```

Valid values: `"low"`, `"medium"`, `"high"`, `"max"`. When combined with `/effort` (which sets the *requested* level), the actual effort used is the lower of the two. Useful for enterprise teams managing costs or enforcing consistent behavior across seats.
