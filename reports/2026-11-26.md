## Featured: Mutation Testing for AI-Generated Code

ThoughtWorks Technology Radar Volume 35 highlights **mutation testing** as a critical guardrail for AI-generated test suites. The problem: coding agents can generate tests with high line coverage that don't actually detect logic changes — syntactically valid but logically toothless.

**What it is:** Mutation testing introduces small changes (mutations) to your source code — flipping operators, changing constants, removing calls — then runs your test suite against each mutant. Tests that fail to catch mutations are exposed as weak.

**Why it matters now:** As coding agents write more tests, teams are discovering that coverage numbers lie. A 95% coverage suite generated by an agent may have a mutation score of 40%, meaning 60% of real bugs would slip through. The Radar now recommends mutation testing as a default check on AI-generated code.

**Quick usage with Claude Code:**
```bash
# Example: run Stryker mutation testing on JS/TS after agent generates tests
npx stryker run

# Or for Python projects with mutmut
mutmut run --paths-to-mutate=src/

# Add as a hook in .claude/settings.json to run after test generation
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write(file_path:*test*)",
      "command": "npx stryker run --mutate 'src/**/*.ts'"
    }]
  }
}
```

**Trade-off:** Mutation testing is slow — expect 10-100x the runtime of your normal test suite. Run it on changed files only, or as a periodic CI gate rather than on every commit.
