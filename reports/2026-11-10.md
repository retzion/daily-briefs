## Featured: `ReadNotifications` Tool (Event-Driven Session Inbox)

Claude Code sessions can receive asynchronous events through the `ReadNotifications` tool — a built-in inbox that queues GitHub activity, scheduled triggers, and messages from other Claude sessions.

**Why it matters:** This is the mechanism that makes Claude Code event-driven rather than purely interactive. When you subscribe to a PR, set up a routine, or have another session send you a message, those events land in the notification queue and wake the session automatically. Without it, features like PR babysitting, scheduled routines, and cross-session collaboration wouldn't work.

**What gets queued:**
- **GitHub PR events** — comments, reviews, CI status changes from subscribed PRs
- **Scheduled triggers** — cron-based routines and self-scheduled wakeups
- **Cross-session messages** — messages sent via `SendMessage` from other Claude sessions

**Usage example:**
```
# In a Claude Code session, after being woken by a notification:
# The system calls ReadNotifications automatically

# Returns queued events oldest-first, marks them delivered
# Large batches come in parts — keep calling until 0 remaining

# Typical flow:
# 1. Subscribe to a PR with subscribe_pr_activity
# 2. End your turn (session goes idle)
# 3. A CI failure wakes the session
# 4. ReadNotifications delivers the event
# 5. You investigate and push a fix
# 6. Session goes idle again, waiting for the next event
```

This is what powers the "fire and forget" workflow: create a PR, subscribe, and walk away. Claude Code handles CI failures and review comments on its own, notifying you only when it needs your input.
