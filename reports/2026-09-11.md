## Featured: `claude plugin eval`
A built-in CLI command for running graded evaluation suites against Claude Code plugins. It answers the question every plugin author hits: "does my plugin actually work when an agent uses it?"

**What it does:** Reads test cases from an `evals/` directory (configurable). Each case is a prompt plus a graders directory defining what a good answer looks like. By default, it also runs every case *without* the plugin loaded, so the score is comparative — you see what the plugin adds, not just whether Claude can answer.

**Why it's useful:** Catches plugins that never activate, silently degrade output, or conflict with other skills. Essential for CI gates before publishing to a marketplace.

**Quick usage:**
```bash
# Run evals for the current plugin
claude plugin eval

# Run against a specific plugin with a custom eval directory
claude plugin eval --plugin ./my-plugin --evals ./test-cases

# Output JSON report for CI integration
claude plugin eval --json
```

The ecosystem has expanded around this: UiPath's `coder_eval` adds sandboxed YAML suites and A/B experiments, and Adversa's CPV runs offline static analysis against the Claude Code plugin spec.
