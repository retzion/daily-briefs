## Featured: `permissions.blockWritesOutsideWorkingDirectories` (Write Guard)

Added in the Oct 30 changelog, this setting prevents Claude Code from writing, editing, or creating files outside your designated working directories. It's a simple on/off toggle in your project or user settings.

**What it is:** A permissions setting that restricts all file-write operations (Write, Edit, NotebookEdit, and shell writes) to paths inside your working directory tree. Any attempt to write elsewhere is blocked before it reaches the filesystem.

**Why it's useful:** Defense-in-depth for agentic workflows. When Claude Code runs in auto mode, background sessions, or routines, an errant write to `/etc`, `~/.ssh`, or another project can cause real damage. This setting eliminates that class of risk with zero workflow friction for normal development.

**Usage:**

In `.claude/settings.json` (project-level):
```json
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}
```

Or in `~/.claude/settings.json` (user-level) to apply everywhere.

**When to use it:** Recommended for any team running Claude Code in auto mode, CI/CD pipelines, or cloud sessions. Pairs well with `--restricted` mode for maximum lockdown.
