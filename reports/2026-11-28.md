## Featured: `ScheduleWakeup` Tool (Dynamic Loop Self-Pacing)

When running a `/loop` task, Claude Code agents don't have to wake up on a fixed timer. The `ScheduleWakeup` tool lets a looping agent decide *when* to check back based on what it's actually waiting for.

**Why it's useful:** Fixed polling intervals are wasteful — a CI run that takes 8 minutes doesn't need eight 60-second checks. `ScheduleWakeup` lets the agent match its delay to the situation:

- **Polling external state** (CI, deploy, remote queue): pick a delay matching how fast that state changes — e.g., one ~480s check for an 8-minute CI run
- **Long fallback heartbeat** (when another signal is the primary wake): 1200s+ so quiet wakeups stay rare
- **Idle ticks with nothing to watch:** Default to 1200–1800s (20–30 min)

**Key features:**
- `noop: true` marks "nothing changed" ticks, which collapse in the terminal view so long quiet holds don't clutter the scroll
- `reason` field explains the delay to the user ("watching CI run" beats "waiting")
- `stop: true` ends the loop immediately

**Quick example:**
```
// After kicking off a CI run that typically takes ~10 minutes
ScheduleWakeup({
  delaySeconds: 600,
  noop: false,
  reason: "CI run started, checking back in ~10 minutes",
  prompt: "/babysit-pr"
})
```

This is what powers the intelligence behind routines like this daily brief — the agent self-paces rather than burning cycles on fixed intervals.
