## Featured: `WebFetch` Tool (In-Session Web Reading)

**What it is:** `WebFetch` lets Claude Code fetch and read web pages, API responses, documentation, and other HTTP content directly during a session. Unlike `WebSearch` (which queries search engines), `WebFetch` retrieves a specific URL and returns its content for analysis.

**Why it matters:** Many coding workflows require reading external resources: checking API docs, verifying deployment status pages, reading changelogs, pulling JSON from an endpoint, or reviewing a linked GitHub issue. Without `WebFetch`, you'd have to copy-paste content into the conversation manually. With it, Claude Code can follow links, read referenced documentation, and verify information at source — all in-session.

**Usage examples:**
```
# Ask Claude Code to read a specific page
"Read the migration guide at https://docs.example.com/v3/migration"

# Verify an API endpoint
"Fetch https://api.example.com/health and check the response"

# Review linked context
"Read the RFC linked in this issue and summarize the breaking changes"
```

Claude Code uses `WebFetch` automatically when you share a URL or when it needs to verify information from a search result. It respects the session's network policy and proxy configuration, and content from fetched pages is treated as untrusted data.

**Tip:** Pair `WebFetch` with `WebSearch` for a research workflow: search to find relevant pages, then fetch to read them in full.
