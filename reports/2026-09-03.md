## Featured: `managedMcpServers` (Enterprise MCP Server Governance)

Organizations running Claude Code at scale now have a dedicated managed setting — `managedMcpServers` — that lets admins deploy HTTP/SSE MCP servers to every user and control which servers employees can connect to.

**Why it matters:** Without governance, any developer can connect any MCP server to their Claude Code session. For regulated industries or security-conscious teams, this is a gap. `managedMcpServers` closes it with allowlist/denylist enforcement.

**How it works:**
1. An admin deploys a `managed-mcp.json` file to a system-wide directory (or uses the enterprise managed settings API).
2. Claude Code loads only the servers that file defines, plus in-process servers the host app registers.
3. Users cannot add, modify, or use any other MCP servers — including plugin-provided ones or `--mcp-config` CLI overrides.

**Quick check:** After setup, verify with:
```
claude mcp list
```
If a server is missing, it was blocked by the allowlist. See the [Managed MCP docs](https://code.claude.com/docs/en/managed-mcp) for configuration details.
