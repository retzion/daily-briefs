## Featured: `CronCreate` / `CronList` / `CronDelete` (In-Session Routine Management)

While [Routines](https://code.claude.com/docs/en/claude-code-on-the-web) were featured back in April as a concept, the actual **cron management tools** deserve their own spotlight — they're what let you create, inspect, and tear down scheduled tasks from within a live Claude Code session.

**What they do:**
- `CronCreate` — schedules a recurring prompt to fire on a cron schedule (e.g., daily at noon UTC). The prompt is stored and fires automatically, spawning a new cloud session each time
- `CronList` — lists all active routines on the account with their schedules, last-fired times, and trigger IDs
- `CronDelete` — removes a routine by its trigger ID

**Why it matters:** This is how you build autonomous workflows entirely from within Claude Code — no external scheduler, no CI pipeline, no cron tab on a server. The daily briefing you're reading right now is powered by exactly this mechanism: a `CronCreate`-scheduled routine that fires every day, runs research, writes a report, and pushes it to git.

**Quick example:**
```
# From within a Claude Code session, ask Claude to:
"Set up a daily routine that checks our staging environment 
health and notifies me if any endpoint returns a 5xx"

# Claude will use CronCreate to schedule it, and the routine
# will fire on its own, use PushNotification to alert you,
# and optionally commit logs to your repo
```

**Key details:**
- Routines run in isolated cloud sessions with full tool access
- Each firing gets its own session context (no carryover between runs)
- Use `CronList` to audit what's running; `CronDelete` to clean up
- The routine's prompt is the stored task — make it self-contained
