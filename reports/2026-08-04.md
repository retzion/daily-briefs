## Featured: Nested Workflows (`workflow()` function)

Claude Code's Workflow tool lets you orchestrate multi-agent scripts with `agent()`, `parallel()`, and `pipeline()`. The `workflow()` function adds composability — you can call a saved or file-based workflow from within a parent workflow, reusing proven patterns without copy-pasting scripts.

**Why it's useful:** As your workflow library grows, you end up with battle-tested scripts for common tasks (review, test, migrate). `workflow()` lets you compose them into larger pipelines — run your review workflow, feed its output into a fix workflow, then run verification — all as a single orchestrated run.

**Usage example:**
```javascript
export const meta = {
  name: 'review-and-fix',
  description: 'Review code, then fix confirmed issues',
  phases: [{ title: 'Review' }, { title: 'Fix' }],
}

phase('Review')
const reviewResult = await workflow('find-bugs', { path: 'src/' })

phase('Fix')
const confirmed = reviewResult.confirmed.filter(b => b.severity === 'high')
await pipeline(
  confirmed,
  bug => agent(`Fix this bug: ${bug.desc} in ${bug.file}`, {
    isolation: 'worktree',
    phase: 'Fix'
  })
)
```

The child workflow shares the parent's concurrency cap, agent counter, and token budget. Nesting is one level deep (a child cannot call `workflow()` again). You can also invoke by file path: `workflow({scriptPath: '/path/to/script.js'}, args)`.
