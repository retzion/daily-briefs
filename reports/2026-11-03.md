## Featured: Message Threads (Messages API)

Launched in public beta on November 2, **Message Threads** eliminate the need to resend full conversation history on every API turn.

**How it works:** On the first request, include the full conversation with a `thread` parameter. The API stores the conversation and Claude's reply under the response ID. Subsequent turns send only new messages plus `previous_message_id` — the server reconstructs the full context server-side.

**Why it matters:** For long-running agents with large contexts (500K–1M tokens), median time-to-first-token drops ~35%. Token pricing is unchanged — Claude still reads the full conversation — but the network transfer and latency savings are significant for agentic workflows.

**Quick usage:**
```python
# First turn — full conversation
response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=1024,
    thread={"id": "thread_abc123"},
    messages=[{"role": "user", "content": "Hello"}],
    betas=["message-threads-2026-08-12"]
)

# Subsequent turns — only new messages
response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=1024,
    thread={"id": "thread_abc123"},
    previous_message_id=response.id,
    messages=[{"role": "user", "content": "Follow up question"}],
    betas=["message-threads-2026-08-12"]
)
```

**Caveats:** Threads expire 5 minutes after last request. Not available for zero-data-retention or HIPAA accounts. Apps must still maintain their own conversation history as a fallback.
