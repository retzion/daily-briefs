## Featured: `permissions.denyInsteadOfPrompting`

A new Claude Code setting introduced in the November releases that automatically denies tool calls that would normally trigger a permission prompt, instead of blocking and waiting for user input.

**Why it matters:** In headless environments — CI/CD pipelines, scheduled routines, background agents, `claude -p` piped workflows — a stalled permission prompt is a silent hang. Previously you had to carefully pre-allow every tool pattern via `permissions.allow`. Now you can set `denyInsteadOfPrompting: true` as a safety net: any call you didn't explicitly allow gets denied immediately, with the denial reason logged, rather than blocking indefinitely.

**Usage:**

In your `.claude/settings.json` or `settings.local.json`:
```json
{
  "permissions": {
    "denyInsteadOfPrompting": true,
    "allow": [
      "Read",
      "Glob",
      "Grep",
      "Bash(git status)",
      "Bash(npm test)"
    ]
  }
}
```

Claude Code will execute allowed tools normally and immediately deny everything else, returning a structured denial the model can see and adapt to. Combine with `--restricted` mode for maximum lockdown in untrusted automation contexts.
