- **v2.1.292** (Oct 6): Added `--marketplace` flag to `claude plugin install` — adds the marketplace source and installs in one step. Added `effort` parameter to the Agent tool. Added `prompt.autocomplete` and prompt caching for `$.model.complete` in mods. Security fixes for UNC path reads and `rm -rf` edge cases on Windows. Local stdio MCP servers now negotiate protocol version 2026-07-28 by default.
- **v2.1.291** (Oct 6): Fixed regression where cloud sessions could drop answers to permission prompts.
- **v2.1.290** (Oct 5): Added `claude attach <name>` / `claude logs <name>` accepting partial session names. Added `/claude-api managed-agents-onboard` for Managed Agents setup patterns. Fixed scheduled tasks not resuming after compaction.

## Featured: `--marketplace` flag for `claude plugin install`

**What it is:** A new convenience flag (v2.1.292+) that combines two steps into one when installing a plugin from a marketplace you haven't added yet.

**Before (two commands):**
```bash
claude plugin marketplace add anthropics/claude-plugins-official
claude plugin install my-cool-plugin@claude-plugins-official
```

**After (one command):**
```bash
claude plugin install my-cool-plugin --marketplace anthropics/claude-plugins-official
```

**Why it matters:** Plugin discovery and installation is a growing part of the Claude Code ecosystem, with mods and plugins becoming central to customization. This flag reduces friction for trying new plugins — especially useful when a colleague or blog post shares a plugin name with its marketplace source. The flag accepts GitHub `owner/repo`, git URLs, or local paths, following the same policy checks as `claude plugin marketplace add`.

Source: [Claude Code Plugin Docs](https://code.claude.com/docs/en/discover-plugins)
