## Featured: Remote Agent Isolation (`isolation: "remote"`)

When spawning a subagent with the `Agent` tool, you can set `isolation: "remote"` to launch it in a remote cloud environment instead of running it locally. Unlike `isolation: "worktree"` (which creates a local git worktree), remote isolation spins up an entirely separate cloud container.

**Why it matters:** Long-running tasks — large refactors, extensive test suites, multi-file code generation — can run in the cloud without tying up your local session's resources or context window. The agent always runs in the background and you're notified when it completes.

**When to use it:**
- Tasks that take 10+ minutes and don't need real-time interaction
- Heavy compute work (building, testing) you want offloaded
- Running multiple independent workstreams in parallel without local resource contention

**Quick example:**
```
Agent({
  description: "Migrate auth module to new API",
  prompt: "Refactor the auth module from v1 to v2 API...",
  isolation: "remote"
})
```

The remote environment gets a fresh clone of the repo, runs independently, and reports back when done. Combined with worktree isolation for lighter local tasks, you can tier your agent orchestration by weight.
