## Featured: Gateway Hint Headers
Claude Code v2.1.273 (Sep 15) ships five new HTTP request headers that give LLM gateways visibility into what Claude Code is doing:

| Header | What it carries |
|--------|----------------|
| `x-claude-code-request-class` | Request type (e.g. `primary`, `subagent`, `compaction`) |
| `x-claude-code-agent-type` | Which agent tier made the call (e.g. `main`, `explore`, `plan`) |
| `x-claude-code-prev-tool-durations` | Timing data from the previous tool calls |
| `x-claude-code-compaction` | Whether this turn involves context compaction |
| `x-claude-code-context-compacted` | Whether context has already been compacted |

**Why it matters**: If you run Claude Code through a gateway (Helicone, Portkey, LiteLLM, or a custom proxy), these headers let you:
- Route subagent requests to cheaper models while keeping the main session on Opus/Fable
- Track per-agent-type token spend for cost attribution
- Prioritize interactive requests over background compactions
- Build dashboards showing which agent types consume the most tokens

**Quick setup**: No configuration needed — the headers are sent automatically. Your gateway just needs to read them. Example Helicone custom property mapping:
```
x-claude-code-request-class → Helicone-Property-RequestClass
```
